# Xui documentation

`www` contains the authored DocFX site, generated documentation figures, static
landing-page assets, and the custom DocFX template. Follow the repository-root
`AGENTS.md` first.

## Directory map

- `www/docs` — authored Markdown and section `toc.yml` files.
- `www/docs/img` — images used by authored docs. Canvas SVGs under
  `www/docs/img/canvas` are generated by `Xui.Tests.Docs`.
- `www/index` — static site-root assets and landing page.
- `www/templates/xui` — custom DocFX template assets.
- `www/api` — configured output for generated API metadata.
- `_site` — generated site output; never edit or commit it.

## Authored documentation

- Preserve the YAML frontmatter used by existing pages (`title` and
  `description`).
- Keep examples aligned with the current .NET 10 projects and public APIs.
- Use paths and commands relative to the repository root unless the surrounding
  page explicitly documents another working directory.
- Use relative Markdown links within `www/docs`.
- When adding, moving, or renaming a page, update the nearest `toc.yml` and any
  inbound links in the same change.
- Prefer short executable examples over copied implementation detail. Public API
  reference belongs in generated metadata, not duplicated prose.
- State incomplete or platform-specific behavior explicitly; do not present
  interface shape as proof of runtime support.

## Generated content

Canvas figures are generated by:

```sh
dotnet test Xui/Tests/Docs/Xui.Tests.Docs.csproj
```

The generator writes `www/docs/img/canvas/*.svg` and always passes. Treat the
SVG diff as the validation result: inspect it before committing. Change the view
source under `Xui/Tests/Docs/Canvas/Views`, not generated SVG markup by hand.

API metadata is configured in `docfx.json` and generated with:

```sh
docfx metadata docfx.json
```

Before relying on API metadata generation, resolve these current repository
inconsistencies as part of a deliberate docs-tooling change:

- `docfx.json` still references the removed
  `Xui/Middleware/EmulatorLegacy/Xui.Middleware.EmulatorLegacy.csproj`.
- `CONTRIBUTING.md` describes committed `www/api` YAML and a hand-maintained
  `www/api/toc.yml`, while `www/api` is currently absent and the repository
  ignores `api/`.

Do not manufacture or restore an API TOC based only on the old instructions.
First decide the intended generated/committed policy, then update configuration,
ignore rules, contributor guidance, and CI together.

## Building the site

Install DocFX only if it is unavailable:

```sh
dotnet tool install --global docfx
```

Build or serve without implicitly regenerating metadata:

```sh
docfx build docfx.json
docfx build docfx.json --serve
```

Use the explicit `build` subcommand. Running bare `docfx docfx.json` can also
execute metadata generation and overwrite API navigation.

The GitHub Pages workflow performs these steps on Windows:

1. Run `Xui.Tests.Docs` in Release.
2. Run `docfx metadata docfx.json`.
3. Run `docfx build docfx.json`.
4. Upload `_site`.

For an authored Markdown-only change, a DocFX build is sufficient. For generated
figures, run the Docs tests first. For public API or metadata changes, validate
the metadata policy and then reproduce the workflow.
