# Instruction graph and stack tree

`Analyzer.Analyze(module, methodHandle)` builds a method-local graph with a node for every decoded instruction. Each reachable node references its `Before` and `After` stack states. Jumps link directly to instruction nodes; conditional branches and switches propagate the same post-instruction stack to all successors. A work queue follows edges, including backward and arbitrary jumps. The first incoming edge establishes a node's state. Matching edges need no further work. Class references can widen to a common same-module base type, including null/class joins; a widened state is interned in the same tree and the affected instruction is requeued. Other mismatches throw with the source and destination IL offsets. Unreachable nodes retain null stack annotations and expose `IsReachable = false`. Their original opcodes and offsets remain in the graph. The conditional WASM emitter skips them without rewriting the source PE; physically deleting IL bytes would instead require adjusting branch, switch, and other affected offsets.

A `StackTree` owns the empty root and interns every pushed prefix. `state.Push(type)` reuses the child for that type or creates it once; `state.Pop()` returns its parent. Walking parents reconstructs the complete stack. States are reference objects with stable identity, not value-equality records. Instructions share pointers to those states instead of retaining copied arrays. Identity is meaningful within one method's tree. These states describe types, not runtime values, so pushing different integer values produces the same state when their prefix is the same.

`Lowest` retains the shortest prefix visited while consuming an instruction's operands. This matters when the exit state alone hides an input: `neg` has identical `Before` and `After` pointers, and `dup` reads an input even though it leaves the original value on the runtime stack. `StructuredBlocks.Build(graph)` uses this information to derive block signatures. It finds natural loops from back edges, collapses nested loops while finding common continuations, and reconstructs `SequenceBlock`, `InstructionBlock`, `ConditionalBlock`, `SwitchBlock`, `LoopBlock`, and `LoopTransfer` nodes. Each conditional records the untouched `Preserved` prefix, bottom-to-top `Parameters` and `Results`, its two arms, and its join. If both arms terminate, the join is null. The minimum depth touched inside either arm determines which incoming values must be block parameters; the join supplies the result suffix. The WASM backend declares these signatures in the type section and emits typed `if`/`else`, including multiple results. Loop headers supply the parameter suffix passed on every back edge; their common exits supply the result suffix. `LoopTransfer` represents continue and break edges. These transfers read their label arguments, so their target's preserved prefix also contributes to enclosing conditional inputs. The loop's lowest touched prefix remains outside both its WASM `block` and `loop`. Forwarding nops and unconditional jumps on break paths may be absorbed when they lead to the same exit. Loops require one entry and one common continuation. Switches retain distinct target arms, case-to-arm indices, a default arm, and typed input/result suffixes. The backend emits nested landing blocks and `br_table`; shared case labels use the same arm. Terminal arms do not contribute continuation stack or local-initialization state. Multiple-entry cycles, loops without a continuation, and overlapping regions still throw; no dispatch loop is generated.

Stack categories include `Int32`, `Int64`, `NativeInt`, `Float`, `String`, `StringArray`, `ValueType`, `ManagedPointer`, `ObjectReference`, and `Null`. Each `StackEntry` retains a declared signature type when its category alone is insufficient: structs carry a module-qualified metadata identity, and managed addresses carry their exact element type. Equal-sized structs remain distinct, as do identical metadata tokens from different modules. Small integer value loads normalize to `Int32`, and floating-point loads normalize to `Float`; addresses of those storage types remain distinct. Block parameters and results retain the complete entries. `StringArray` retains the entry-point parameter type; the backend still rejects access to entry-point arguments.

`DotNet.Signatures.SignatureReader` supplies shared declared types for parameters, results, locals, and fields. Supported analysis effects include constants, argument/local loads and stores, managed addresses, duplication/discard, unchecked arithmetic and bitwise operations, numeric comparisons and conversions, direct branches, switches, returns, and non-generic calls. Same-module class/value-type constructors, direct instance calls, fields, and object-copy/initialization instructions are analyzed with exact struct identities. Calls use MethodDefinition or MemberReference signatures without analyzing or executing the callee. The backend now supports linear struct locals, GC classes, and GC structs with value copies; the original NFloat Point/Vector demo still stops at its external conversion calls.

Unsupported opcodes, generic method signatures, unsupported reference joins, and exception filters throw explicitly. Null can be assigned to class/interface/object/string storage; class joins can widen their canonical states to a common same-module base, an existing assignable interface, or an existing object stack type. Class-backed object storage uses GC references; boxed values and string-to-object conversions remain unsupported. Type references into explicitly supplied `XuiNet.Compilation` assemblies resolve to their defining modules. Call signatures are read from the resolved method owner. This is a stack-type analysis, not a complete CLI verifier: it does not check definite local initialization or the full set of CLI type-compatibility rules.

Tests cover interning, joins, loop back-edges, non-linear traversal, dead instructions, and branches that consume existing stack entries and produce multiple results. Snapshots show C# source and every instruction's edges, `Before`, `After`, and `Lowest` states for Debug and Release, followed by the shared stack tree.

[WASM control-flow demos](../../Tests/Wasm/CodeFlow/README.md) execute conditional and loop variations in Node and snapshot source, output, exit code, and WAT.

`Analyzer.Analyze(module, MethodIdentity)` supplies a constructed declaring-type context. Generic class arguments substitute into locals, calls, and fields before stack effects are applied. Type identity includes the argument vector; generic method parameters remain unsupported by emission. The original method-handle overload continues to analyze nongeneric declaring types.

`ExceptionBlocks.Build(module, body, graph)` composes lexical protected regions with
conditional/loop reconstruction. Catch entry stacks contain the declared exception;
finally/fault entries start empty. Handler roots are analyzed conservatively, and
`leave` clears the evaluation stack. `ExceptionBlock` records the protected body,
ordered handlers, and a single normal continuation. A finally with no reachable
`endfinally` makes its normal continuation unreachable. Filters, overlapping scopes,
and multiple normal continuations are rejected; no dispatcher is synthesized.

The recognized framework NFloat intrinsic normalizes to the floating stack category.
The WASM backend separately enforces target f32 storage/call/operation rounding;
assembly metadata views and layout identities remain nominal.
