# Generic class specialization

[Boxes](Snapshots/Boxes.md) compiles the same `Box<T>` declaration as `Box<int>` and `Box<string>`. Constructors, instance methods, static methods, fields, arguments, results, and Debug locals substitute `T` before layout and emission. The snapshot shows source, output, exit code, and separate typed WASM methods. Its [assembly snapshot](../../XuiNet/DotNet/Snapshots/Boxes.md) shows generic parameters, `TypeSpec` rows, and member references to constructed types.

Tests compare CLR and Node behavior in Debug and Release, including template overloads, nested and recursive generic references, small integer and float storage, and non-generic GC structs as type arguments. Reader tests verify structural type identity, distinct method specializations sharing one PE method handle, and canonical stack states.

[DerivedBoxes](Snapshots/DerivedBoxes.md) adds a three-level hierarchy with reordered generic arguments, abstract and virtual slots, explicit base calls, and `is`/`as` checks. It displays each runtime type's inherited fields and virtual implementations alongside the WAT. Its [assembly snapshot](../../XuiNet/DotNet/Snapshots/DerivedBoxes.md) exposes the corresponding base TypeSpecs and member references. Additional execution tests cover distinct `new virtual` slots, template overloads that become identical after specialization, virtual calls inside constructors, nested base arguments, hidden and flattened fields, GC struct value copies, and control-flow joins at a constructed base.

Closed, same-module generic classes support inheritance and non-generic virtual/abstract methods. Generic methods (`MethodSpec`), generic structs, and primitive/reference `default(T)` paths requiring `initobj` remain unsupported. Argument types must already have supported storage and calling conventions. Generic nesting is limited to 32 levels so expanding generic graphs fail explicitly. Constraint declarations are exposed by the reader; this is not a full CLI constraint verifier.
