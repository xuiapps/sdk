# Xui Compiler

The compiler infrastructure follows a C# → managed PE/MSIL → WebAssembly pipeline, with all projects included in the root `Xui.sln`. [XuiNet](XuiNet) opens a PE image and exposes assembly, module, type, and member views under `DotNet`. The assembly owns the retained PE reader; metadata blobs and method bodies are read on demand. `ILReader` reads opcodes, and specialized `Instruction` ref structs consume their typed operands without building an instruction array. Borrowed views must be used before disposing the assembly. [Roslyn](Tests/Frontend/Roslyn.cs) currently lives in the tests as a frontend for compiling fixture source into PE bytes.

[Reachability](XuiNet/Reachability/README.md) discovers dependencies before backend planning. It accepts method, type, and assembly roots, with all-member or public-API preservation. Applications start from the managed entry point; unused classes and their methods are never planned. The frozen graph records layouts, field access, closed generic specializations, conditional virtual targets, initializer dependencies, and host rewrites, with reasons and IL offsets. Instance layouts remain intact. `XuiNet.Compilation` binds an explicit set of implementation assemblies, resolves named types and member signatures, and lets reachable primitive/string static calls from those assemblies share one WASM module. Supplying a library does not root it. Cross-assembly object/struct storage, type forwarding, and BCL compilation remain future work.

[WasmEmitter](WASM/Emitter/WasmEmitter.cs) organizes the module layout, while the `ref struct` [CodeEmitter](WASM/Emitter/CodeEmitter.cs) reads MSIL and emits each supported opcode through a dedicated method. Both live in the `Emitter` namespace and use the independent types and binary writers in [WASM/Wasm](WASM/Wasm). `ModuleWriter` composes a `.wasm` blob through disposable section writers, with enums for encodings and distinct index types. The backend supports string and numeric constants (including i64), `dup`/`pop`, unchecked addition/subtraction/multiplication/negation, integer bitwise operations and shifts, numeric comparisons, integer conversions, and conversions to floating point. Primitive and string locals use typed WASM slots, with narrowing and float rounding on stores. Unmanaged struct locals use aligned linear-memory frames with byte copies, nested field access, and struct-local addresses. Addressable structs containing strings or objects use frame-owned reference-table slots, with `ref`/`in`/`out` calls, independent value copies, and cleanup during unwinding; see the [stack event demo](Tests/Wasm/ReferenceSlots/Snapshots/Events.md). Other classes and reference-containing structs use WASM GC objects, with value copies for structs and recursively flattened struct fields. Closed generic classes specialize their layouts, signatures, fields, and methods for each reachable argument list, including inherited fields and virtual/abstract dispatch across constructed base types. Class hierarchies preserve inherited fields; virtual and abstract class calls use function-table slots, and class/interface `is`/`as` tests use nominal runtime type descriptors. Interfaces support implicit/explicit class implementations, inherited and reimplemented mappings, and closed invariant generic contracts. Interface calls use a shared prefix of each class’s function table; `object` locals, fields, parameters, and returns can carry emitted class/interface references. Default interface bodies use the most-specific implementation when no class implementation exists, including closed generic contracts and linked assemblies. Unselected default bodies are omitted. Closed generic methods specialize through MethodSpec, including linked calls. Single-target delegates retain their target and a function-table entry; Invoke supports static, instance, virtual/interface, and captured callbacks. See the [closure demo](Tests/Wasm/Delegates/Snapshots/Closures.md). Multicast Combine/Remove and equality preserve ordered, immutable invocation lists; see the [multicast demo](Tests/Wasm/Delegates/Snapshots/Multicast.md). Generated event accessors use reference CompareExchange in the single-threaded runtime; compiler-generated static callback caches remain unsupported. Reference byrefs use an owner/selector pair with generated field accessors; local/argument reference slots are frame-owned and cleared on unwinding. Value-type boxing, static-abstract dispatch, and generic virtual methods remain unsupported. Native WASM exception tags support typed catches, throw/rethrow, finally/fault, and catchable cast/null failures for a small built-in exception surface; see the [exception demo](Tests/Wasm/Exceptions/Snapshots/Casts.md). Filters and custom exception subclasses remain unsupported. See the [interface demo](Tests/Wasm/Interfaces/Snapshots/Units.md). [Runtime.Type](WASM/Runtime/Type.cs) exposes the compiler metadata for a future managed type API. Native integer locals and conversions use 32 bits. Reachable closed static methods in the supplied assemblies support primitive/string arguments and results, argument loads/stores, and forward calls. Entry points can return `void` or `int`. Generic virtual/unresolved external calls, type/module initialization, and access to entry-point arguments remain unsupported. Floating-point-to-integer conversions, native-integer arithmetic, checked arithmetic, division/remainder, switches, and arbitrary jump graphs remain unsupported and throw during emission. For conditional methods, [CodeFlow](XuiNet/CodeFlow) analyzes interned stack states and reconstructs nested `if`/`else` blocks and single-entry loops. Typed block inputs and multiple results preserve existing stack values and support ternaries, early returns, and values carried across loop iterations. `while`, `do while`, `for`, nested loops, and structured `break`/`continue` share typed loop labels. The MSIL type stack selects integer or floating-point addition, using f64 for the floating-point evaluation category. String literals are stored as UTF-16LE data segments, converted on first use through `wasm:js-string.fromCharCodeArray`, and cached as JavaScript strings. `EmissionRuntime` groups the required string type/function indices and optional frame stack-pointer global. An optional [CodeRewriter](WASM/Emitter/Rewrite/CodeRewriter.cs) gets first chance to collect requirements and replace each instruction, and declares its own types and imports. The default `NoOpCodeRewriter` leaves instructions unchanged.

[Tests/Fixtures](Tests/Fixtures) contains shared C# inputs. The [XuiNet tests](Tests/XuiNet/DotNet/README.md) traverse assemblies depth-first and compare Markdown snapshots of metadata, signatures, IL, and exception regions. The [three-assembly demo](Tests/Wasm/Repl/MultiAssembly/Snapshots/ThreeAssemblies.md) compiles separate fixtures into application and library PEs, follows calls between them, and verifies unused declarations are omitted. The [WASM REPL tests](Tests/Wasm/Repl) and dedicated [control-flow demos](Tests/Wasm/CodeFlow/README.md) explicitly supply a [ConsoleWriteLineRewriter](Playground/ConsoleWriteLineRewriter.cs), execute emitted modules in Node, and snapshot the C# source, captured output, main exit code (zero for void), and WAT. This host policy maps string and numeric output to `xui.console-log`, rounds `float` arguments to f32, and maps Boolean output to `xui.console-log-boolean` for .NET-style `True` and `False`. Numeric formatting otherwise follows JavaScript. A small wrapper pipes WASM into `wasm-tools print` and captures its stdout. With .NET 10, Node supporting JS string builtins, WASM GC, and `try_table`, and `wasm-tools` on PATH, run `dotnet test Xui/Compiler/Tests/Xui.Compiler.Tests.csproj -c Release` from the repository root. Snapshot mismatches produce `.received.md` files; set `XUI_UPDATE_SNAPSHOTS=1` to intentionally regenerate expectations, then review the changes.

[Playground](Playground/README.md) is a static browser REPL served at `/wasm/` by the Pages workflow. A persistent .NET WebAssembly worker hosts Roslyn and the compiler; each emitted WASM program executes in a separate disposable worker. It includes source editing, console output, diagnostics, exit codes, Stop, and WASM downloads. The playground and Node tests share the optional console rewrite.

The [standalone canvas demos](Tests/Wasm/Canvas/README.md) now compile real Xui Core
Rect/Color types from a separate implementation assembly into one WASM module.
The generated HTML embeds JavaScript and WASM, opens directly from disk, and draws
rectangles and text without downloading a runtime. Shapes, a computed grid, and a
ref-event/interface demo are verified in Node and offline Chromium. These use a small
host adapter; the full Window/View lifecycle remains future work.

The next TestApp milestone now has an executable [construction gate](Tests/Wasm/TestApp/Snapshots/FillRectConstruction.md)
using unchanged app sources and the real Core DLL. Struct values can cross direct,
virtual, and interface calls; classes can inherit across supplied assemblies with
qualified field identities. The [Values canvas demo](Tests/Wasm/Canvas/Snapshots/Values.html)
executes `Rect.Inset` through this ABI and uses `Point point = (0, 0)` tuple syntax.
Closed generic struct layouts and actual framework ValueTuple constructors now work;
see [Xui tuple geometry](Tests/Wasm/Tuples/Snapshots/XuiGeometry.md). The real
FillRectTest now lays out and renders in the browser phone preview. The
[full-shell probe](Tests/Wasm/TestApp/Snapshots/MobileShellReadiness.md) supplies the
framework assemblies for services and collections. It now passes generated event
subscriptions, ArgumentNullException guards, TimeSpan factories, and the rating
panel’s UTF-16 interpolation and generic interface dispatch for demo navigation.
The full catalogue reaches optional Lazy/async floorplan preloading. The smaller
browser catalogue passes equality, header easing, and navigation array operations;
generic page factories now specialize too. Its next dependency is integer ToString
for the header frame-rate display. Optional preloading also needs Lazy/async support. See [PLAN.md](PLAN.md) for the remaining gates.

Managed vectors and inline arrays now have distinct storage paths. See [array execution](Tests/Wasm/Arrays/Snapshots/Vectors.md)
and [real Xui gradient stops](Tests/Wasm/InlineArrays/Snapshots/Gradients.md): the latter
uses collection expressions, tuple conversions, an inline buffer, and ReadOnlySpan
inside LinearGradient. Numeric inline buffers remain in linear frames; reference
elements use frame-owned handles. The WASM README records the supported array/span
operations and remaining restrictions.

Address-taken scalar locals and arguments now use aligned linear-memory slots.
Primitive, enum, and NFloat ref/in/out calls preserve aliases and exact storage
widths; ordinary scalar locals still use WASM locals. Generic scalar ldobj/stobj/
initobj operations share this storage. Passing inline scalar GC fields by reference
and returning managed addresses remain unsupported.
