# Xui Compiler

The compiler infrastructure follows a C# → managed PE/MSIL → WebAssembly pipeline, with all projects included in the root `Xui.sln`. [XuiNet](XuiNet) opens a PE image and exposes assembly, module, type, and member views under `DotNet`. The assembly owns the retained PE reader; metadata blobs and method bodies are read on demand. `ILReader` reads opcodes, and specialized `Instruction` ref structs consume their typed operands without building an instruction array. Borrowed views must be used before disposing the assembly. [Roslyn](Tests/Frontend/Roslyn.cs) currently lives in the tests as a frontend for compiling fixture source into PE bytes.

[WasmEmitter](WASM/Emitter/WasmEmitter.cs) organizes the module layout, while the `ref struct` [CodeEmitter](WASM/Emitter/CodeEmitter.cs) reads MSIL and emits each supported opcode through a dedicated method. Both live in the `Emitter` namespace and use the independent types and binary writers in [WASM/Wasm](WASM/Wasm). `ModuleWriter` composes a `.wasm` blob through disposable section writers, with enums for encodings and distinct index types. The backend supports string and numeric constants (including i64), `dup`/`pop`, unchecked addition/subtraction/multiplication/negation, integer bitwise operations and shifts, numeric comparisons, integer conversions, and conversions to floating point. Primitive and string locals use typed WASM slots, with narrowing and float rounding on stores. Unmanaged struct locals use aligned linear-memory frames with byte copies, nested field access, and struct-local addresses; classes and reference-containing structs use WASM GC objects, with value copies for structs and recursively flattened struct fields. Closed generic classes specialize their layouts, signatures, fields, and methods for each reachable argument list, including inherited fields and virtual/abstract dispatch across constructed base types. Class hierarchies preserve inherited fields; virtual and abstract class calls use function-table slots, and class `is`/`as` tests follow runtime type descriptors. [Runtime.Type](WASM/Runtime/Type.cs) exposes the compiler metadata for a future managed type API. Native integer locals and conversions use 32 bits. Reachable non-generic static methods in the same module support primitive/string arguments and results, argument loads/stores, and forward calls. Entry points can return `void` or `int`. Generic-method/external calls, type/module initialization, and access to entry-point arguments remain unsupported. Floating-point-to-integer conversions, native-integer arithmetic, checked arithmetic, division/remainder, primitive local addresses, switches, and arbitrary jump graphs remain unsupported and throw during emission. For conditional methods, [CodeFlow](XuiNet/CodeFlow) analyzes interned stack states and reconstructs nested `if`/`else` blocks and single-entry loops. Typed block inputs and multiple results preserve existing stack values and support ternaries, early returns, and values carried across loop iterations. `while`, `do while`, `for`, nested loops, and structured `break`/`continue` share typed loop labels. The MSIL type stack selects integer or floating-point addition, using f64 for the floating-point evaluation category. String literals are stored as UTF-16LE data segments, converted on first use through `wasm:js-string.fromCharCodeArray`, and cached as JavaScript strings. `EmissionRuntime` groups the required string type/function indices and optional frame stack-pointer global. An optional [CodeRewriter](WASM/Emitter/Rewrite/CodeRewriter.cs) gets first chance to collect requirements and replace each instruction, and declares its own types and imports. The default `NoOpCodeRewriter` leaves instructions unchanged.

[Tests/Fixtures](Tests/Fixtures) contains shared C# inputs. The [XuiNet tests](Tests/XuiNet/DotNet/README.md) traverse assemblies depth-first and compare Markdown snapshots of metadata, signatures, IL, and exception regions. The [WASM REPL tests](Tests/Wasm/Repl) and dedicated [control-flow demos](Tests/Wasm/CodeFlow/README.md) explicitly supply a [ConsoleWriteLineRewriter](Playground/ConsoleWriteLineRewriter.cs), execute emitted modules in Node, and snapshot the C# source, captured output, main exit code (zero for void), and WAT. This host policy maps string and numeric output to `xui.console-log`, rounds `float` arguments to f32, and maps Boolean output to `xui.console-log-boolean` for .NET-style `True` and `False`. Numeric formatting otherwise follows JavaScript. A small wrapper pipes WASM into `wasm-tools print` and captures its stdout. With .NET 10, Node supporting JS string builtins, and `wasm-tools` on PATH, run `dotnet test Xui/Compiler/Tests/Xui.Compiler.Tests.csproj -c Release` from the repository root. Snapshot mismatches produce `.received.md` files; set `XUI_UPDATE_SNAPSHOTS=1` to intentionally regenerate expectations, then review the changes.

[Playground](Playground/README.md) is a static browser REPL served at `/wasm/` by the Pages workflow. A persistent .NET WebAssembly worker hosts Roslyn and the compiler; each emitted WASM program executes in a separate disposable worker. It includes source editing, console output, diagnostics, exit codes, Stop, and WASM downloads. The playground and Node tests share the optional console rewrite.
